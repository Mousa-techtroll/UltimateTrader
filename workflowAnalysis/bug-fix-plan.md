## Governing Principles (binding on every iteration)

1. **NO LOGIC CUTTING.** Every fix *repairs* the implementation. We never disable, delete, or short-circuit trading logic to silence a finding. Dead/orphan code is *repaired-and-deprecated* (banner + `#ifdef` fence + corrected magic/filling), never deleted in this pass; advertised-but-dead config (HTF confluence, zone age, price-macro fallback, `InpEnableEngineExpansion`, news DAY_DATA) is *wired up*, not removed. The only "removals" permitted are provably-dead *non-trading scaffolding* (e.g. `g_consecutiveErrors`, `CSignalManager`, dead PBC members) where stok explicitly verified zero trade-path coupling.

2. **The "measured losers" premise is REJECTED.** The prior verdicts on the multi-strategy engine paths (FVG PF 0.61, SFP 0% WR, BB −1.1R, Pullback −0.5R, S6 Short −8.9R) were measured on *buggy implementations* — latched/forming-bar BOS spine, a discarded confluence scorer, non-orthogonal scoring axes, hardcoded confluence constants, a NULL S6 range-box, mislabeled rubber-band mode, an absent short veto. Those bugs are exactly what depressed the old numbers. Each engine/strategy is **implemented correctly** (time/chart/variables/init/impl) and then **validated by a FRESH 2019–2026 XAUUSD H1 backtest** — never judged on the old findings. Intellectual-honesty caveat (stok): a clean re-implementation may *still* find no edge on some paths (FVG-as-momentum and gold's structural uptrend are market facts, not bugs); the plan is built to be able to return that answer. Engines stay **OFF by default** until each path earns ON on fresh decoded numbers.

3. **Any trading-logic change uses stok's `recommended_option`.** Where a fix is `BETTER-OPTION` or `NEEDS-CARE`, the specific stok parameter/option is cited inline in the iteration and is binding. We do not carry v18 tuning constants forward where stok flagged re-derivation.

## Executive Summary

This is a **dependency-ordered, iteration-based** plan to repair 53 verified defects without removing a single line of working trading logic. The dominant theme (≈half the batch) is the **forming-bar `[0]` → closed-bar `[1]`** correction across the SMC/structure/regime/trailing layers — mechanically correct, aligned with the repo's own `GetDrawOnLiquidity`/entry-plugin convention, and (because the EA already throttles to once-per-H1-bar) a systematic *measurement* error rather than intra-bar repaint.

The structural sequencing is deliberate: **scoring depends on market-context primitives, and engine validation depends on the scorer being honored.** Therefore Iteration 1 repairs the market-context foundation (SMC re-scan/latch/forming-bar, swing/MA200/regime closed-bar, macro fallback, crash detector); Iteration 2 wires the discarded `CConfluenceScorer` in and decouples the scoring axes; **Iteration 3 is the multi-strategy engine implementation-revision + per-engine fresh-backtest validation** (the heart of the rejected-premise mandate); Iteration 4 enforces execution/risk (exposure cap, daily-trade limit, spread units, sizing, partial fills); Iteration 5 fixes core/orchestration + persistence (file-signal bypass/executed-before-reject, multi-symbol management, symbol-matched recovery, tp3 persistence); Iteration 6 sweeps infra + hygiene (retcode classifier, logger, dead-code deprecation, doc fixes, remaining med/low).

## QA / Testing Methodology (applied to EVERY iteration)

Every iteration runs the full gate. No fix is "done" on a clean compile alone.

**(a) Compile to 0 errors — the proven MetaEditor gate (negative-control verified).**
Locate binaries first (do not trust stale script paths):
```
find /mnt/c -iname "metaeditor64.exe" 2>/dev/null     # expect: Vantage Markets MT5 Terminal\MetaEditor64.exe
find /mnt/c -iname "terminal64.exe"   2>/dev/null
```
Compile and decode (logs are UTF-16LE):
```
powershell.exe -Command "& 'C:\Program Files\Vantage Markets MT5 Terminal\MetaEditor64.exe' /compile:'<...>\MQL5\Experts\UltimateTrader.mq5' /log:'<...>\mq5-build.log'"
iconv -f UTF-16LE -t UTF-8 mq5-build.log
```
Pass = **0 errors and 0 NEW warnings**; count and quote any. MQL error **106 = include not found** (check relative include path + that the `#include` was added). The negative control: a deliberately-broken include must produce a non-zero error count, proving the gate is live.

**(b) Targeted / isolated backtest of the affected subsystem** via the relevant `Inp*` toggles (e.g. `InpEnablePullbackCont`, `InpEnableEngineTrend`, `InpEnableMultiStrategy`, `InpSignalSource=FILE`, `InpEnableShockDetection`). Decode the UTF-16LE stats CSV in `Logs/` with `iconv` and report **actual** numbers — never estimate.

**(c) A/B vs the current committed baseline** (immediately-prior build, and the locked v18/v19 reference) to confirm no unintended regression *and* to measure the fix's effect. For fixes stok labeled byte-identical/no-op-on-production-path, the A/B **must prove trade-for-trade, SL-for-SL, R-for-R identity** on the XAUUSD-only H1 production config — if it is not identical, the "no-op" claim is wrong and must be reconciled before merge.

**(d) FRESH full 2019–2026 XAUUSD H1 backtest per engine (Iteration 3 only).**
For EACH engine independently (`InpEnableMultiStrategy=true` + only that one `InpEnableEngine*=true`), run the full window via `backtest_symbol.sh XAUUSD <year>`, decode the CSV, record **PF, avg-R, net, trade count, max DD**. Then toggle each composed sub-path to measure its **marginal contribution**. This establishes each engine's REAL edge and **replaces reliance on old findings**.

**(e) Regression gate — default behavior stays unchanged where intended.**
`InpEnableMultiStrategy=false` (default) behavior must be **byte-identical** to baseline. Legacy-plugin (engine-off) signals must be byte-identical. The session-engine-on default clock must return identical values to pre-fix.

### Pass / fail (kill) criteria

- **Per fix (no-op claim):** byte-identical production backtest → PASS; any divergence → reconcile before merge.
- **Per trading-logic fix:** A/B delta is explainable by the fix's stated mechanism, net P&L/maxDD not materially worse, and stok signs off the behavioral shift → PASS; unexplained divergence or stok rejection → loop back (see Iteration Loop).
- **Per engine (Iteration 3):** **KILL if PF < 1.0 OR avg-R < 0 over the full 2019–2026 window AND on the 2024–2026 out-of-sample slice.** An engine that does not beat *or complement* baseline net/DD stays OFF regardless of in-sample PF. Each enabled config must beat or complement the locked v18 $6,140 reference.

## The Iteration Loop (explicit)

After **every** iteration:

1. **Re-run the relevant QA** (compile → isolated backtest → A/B vs prior build + v18 baseline → regression gate on default config).
2. **Decode actual numbers** from the UTF-16LE stats CSV (`iconv`); never estimate.
3. **Evaluate against the iteration's pass/fail (kill) criteria.**
4. **If a fix regresses** (unexplained divergence, no-op claim fails byte-identity, runtime error) **OR a trading-logic change underperforms** (worse net/maxDD without a mechanism, or a kill-criterion trips):
   - **Loop back to stok with the decoded before/after numbers** for the specific fix.
   - stok re-validates the trading rationale and, if needed, supplies a revised `recommended_option` (e.g. a different `SMC_SWEEP_RECENCY_BARS`, `InpBOSFreshnessBars`, `InpSpineMinConfluence`, `InpMinSessionRiskFactor`, re-derived tier thresholds).
   - **Do NOT proceed to the next iteration until the regressed fix is reconciled or explicitly parked** (commented-out at the registration/toggle level only with stok sign-off — never a logic cut).
5. **Land each behavioral fix as a separately-measurable commit** (the two Regime edits 1.4+1.5 as one; the trailing cluster 4.8→4.9→4.10 in order; the multi-symbol bundle 5.3+5.4) so each delta vs the v18 baseline is attributable.
6. **Iteration 3 special loop:** each engine/sub-path that trips the kill-criterion stays OFF and is handed back to stok with its fresh decoded PF/avg-R — it is not re-judged on old findings, and it is not force-enabled to chase trade count.
