## WHY (mechanism)
- **Why no-op in the tester:** the MT5 Strategy Tester is single-symbol — it only ever instantiates positions on the chart symbol (XAUUSD+). Therefore `PositionGetString(POSITION_SYMBOL)` is ALWAYS == `_Symbol` for every broker position the loaders see, so the new AND-condition is always `true` (and the De-Morgan skip-clause is always `false`). No recovery decision changes → byte-identical output. This is the expected, designed result.
- **Why the guard has real value (live, not in the tester):** in production a single MT5 terminal can run UltimateTrader on multiple charts (e.g. gold + another symbol) sharing one magic number. Before this fix, the three startup recovery loaders matched on magic ONLY — so the gold chart could adopt and then MANAGE a foreign-symbol position (its iATR/iHighest/swing/tick math is all gold's), producing a meaningless SL and mis-scaled R. The live OnTick orphan-adoption path already guarded this at `UltimateTrader.mq5:2083-2084`; the recovery loaders were the gap. This fix closes that gap by mirroring the OnTick guard exactly. It is deliberately the single-symbol-per-chart guard only — multi-symbol *management* is out of scope (fix 5.3).
