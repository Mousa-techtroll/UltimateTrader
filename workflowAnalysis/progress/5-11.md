## WHY (mechanism, for stok)
- **XCut-7 (live-only):** after a restart, `ReconcileWithBroker` rebuilt `SPosition` from broker price/volume + persisted internal state, but the persisted schema (v4) had **no tp3 and no entry_risk_amount**. Effects on a restored position:
  1. `has_tp3 = (InpFileUseTP3 && pos.tp3>0)` (CPositionCoordinator ~1711) evaluated false → a 3-way 33/33/34 file-signal ladder **silently degraded to a 2-way 50/50 split** (runner-to-TP3 logic lost).
  2. `entry_risk_amount==0` → `CalculatePositionRiskDollars` fell into the `_Symbol`-tick recompute (~295-312) → for a foreign-symbol / file position this **re-introduces the wrong-symbol R error** that fixes 5.1/5.3 closed.
- v5 persists both fields, so a restored position keeps the full ladder and a symbol-correct money risk basis. signal_id stays out of the struct (FileWriteStruct cannot serialize a dynamic string — it would write a pointer/garbage); if needed later it must be persisted out-of-struct.
- Unmeasurable in the tester (clean start → restore path inactive); byte-identical A/B proves no production regression; correctness rests on the reviewed logic + the harness-proven version/size discrimination.
