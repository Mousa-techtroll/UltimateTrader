### FIX 4.9 — STOPS_LEVEL/freeze clamp + revert-on-reject (`CPositionCoordinator.mqh`, UpdateTrailingStops trailing-commit block ~2727-2945)
- **Clamp (before committing `pos.stop_loss`):** after `normalized_sl` is computed and `old_sl=pos.stop_loss` captured, clamp `normalized_sl` to `min_dist = MathMax(SYMBOL_TRADE_STOPS_LEVEL, SYMBOL_TRADE_FREEZE_LEVEL) * point` from the close-side price (BID for LONG, ASK for SHORT). The clamp ONLY ever moves SL AWAY from market (LONG: push DOWN to `bid-min_dist`; SHORT: push UP to `ask+min_dist`). `gate_reason_clamp` set true iff the value actually moved.
- **Ratchet re-verify (CRITICAL):** after clamping, re-check `clamped_is_better` against `old_sl` (LONG: `>old_sl`; SHORT: `<old_sl || old_sl==0`). If the clamp pushed SL past old_sl (would be a backward move), `continue` — skip the whole update so the stop is NEVER moved backward. (Fires 0x in the run; the clamp here always still beat old_sl.)
- **Commit:** `pos.stop_loss = normalized_sl` (the clamp-valid value) — internal tracking commits ONLY the clamped value.
- **Distinct gate_reason:** if clamped, `gate_reason` gets `+STOPS_LEVEL_CLAMP` (or `STOPS_LEVEL_CLAMP`) appended -> logged + persisted.
- **Revert-on-reject:** on a failed broker `PositionModify`, read `trail_trade.ResultRetcode()`; if `== TRADE_RETCODE_INVALID_STOPS`, revert `pos.stop_loss = old_sl`, revert a newly-armed breakeven, set `gate_reason="INVALID_STOPS_REVERT"` + persist -> internal SL re-synced to what the broker actually holds. Retcode also added to the WARNING log line. (Fires 0x in the run — the clamp prevents the rejection upstream.)
- NO logic cut: the existing `is_better` ratchet, `ShouldSendBrokerTrail` gate, breakeven logic, and logging are all preserved; 4.9 only ADDS the clamp + re-verify + revert.
