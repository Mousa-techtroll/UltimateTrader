## What changed (verified file:line against current source d49b9be)
The four loops were structurally identical pre-fix:
`CopyHigh/CopyLow(_Symbol, PERIOD_H4, 0, 100, arr)` (start_pos=0) then `for(int i = 2; i < 98; i++)`
reading `arr[i-2..i+2]`. Two defects: (a) the loop hardcodes `i<98` and reads `arr[i+2]` (up to index 99)
even when CopyHigh/Low returned <100 bars (warmup) → OOB read → runtime abort [5.8];
(b) start_pos=0 makes the forming H4 bar (shift 0) a pivot neighbor → repaint [5.9].

- `CTradeOrchestrator.mqh::FindNearestObstacle` LONG branch (~1014-1030): `CopyHigh(...,0,100,high)` → capture `n=CopyHigh(...,1,100,high)`; guard `if(n >= 5)`; loop `for(int i=2; i<n-2; i++)`.
- `CTradeOrchestrator.mqh::FindNearestObstacle` SHORT branch (~1058-1074): `CopyLow(...,0,100,low)` → `n=CopyLow(...,1,100,low)`; guard `if(n >= 5)`; loop `for(int i=2; i<n-2; i++)`.
- `CAdaptiveTPManager.mqh::FindNextResistance` (~483-501): `CopyHigh(...,0,100,high)<=0 return 0` → `n=CopyHigh(...,1,100,high); if(n<5) return 0;` loop `for(int i=2; i<n-2; i++)`.
- `CAdaptiveTPManager.mqh::FindNextSupport` (~506-526): `CopyLow(...,0,100,low)<=0 return 0` → `n=CopyLow(...,1,100,low); if(n<5) return 0;` loop `for(int i=2; i<n-2; i++)`.

5.8 + 5.9 implemented together per loop: start_pos 0→1 (5.9) AND `n` capture + `i<n-2` + `n>=5` floor (5.8).
With `i<n-2` every pivot neighbor `arr[i+2]` is bounded; with start_pos=1 the array begins at the last CLOSED
H4 bar so no forming-bar neighbor. NO logic cut — the pivot test (5-bar fractal), the obstacle sources
(PDH/PDL, weekly H/L, round-$50, SMC), and the nearest-selection are all unchanged.
