## Problem (verified at source before edit)
A partial fill was treated as a FAILURE even though a real position is open at the broker; and even when accepted, the position seeded original/remaining/entry_risk from the REQUESTED volume, not the actual filled volume, over-stating position size in R-milestones and partial-TP math.

## What changed (BEFORE / AFTER)

### Edit 1 — `CEnhancedTradeExecutor.mqh` `ValidateExecutedVolume` (1616+)
- **BEFORE:** `if(executedLots <= 0 || MathAbs(executedLots - expectedLots) > 0.001) { validationErrors += "Volume mismatch..."; return false; }`
- **AFTER:** fail ONLY on `executedLots <= 0` (return false with "Zero volume executed"); on a short fill `0 < executedLots < expected` → `Log.Warning("Partial fill accepted: ...")` + `return true`. Thresholds/structure otherwise unchanged. NO logic cut (the all-or-nothing rejection of a real position is replaced by acceptance, which is the fix).

### Edit 2a — `CTradeOrchestrator.mqh:699` lot_size propagation (LOAD-BEARING)
- **BEFORE:** `position.lot_size = lot_size;` (requested lot)
- **AFTER:** `double filled_lots = (exec_result.executedLots > 0.0) ? exec_result.executedLots : lot_size; position.lot_size = filled_lots;` — original_lots/remaining_lots (seeded downstream from position.lot_size) now reflect the ACTUAL filled volume. Guard executedLots>0 (ValidateExecutedVolume already rejected <=0) with requested fallback.

### Edit 2b — `CTradeOrchestrator.mqh:717` entry_risk_amount scaling
- **BEFORE:** `position.entry_risk_amount = position.entry_balance * position.initial_risk_pct / 100.0;`
- **AFTER:** same line, then `if(lot_size > 0.0 && filled_lots != lot_size) position.entry_risk_amount *= (filled_lots / lot_size);` — full fill ⇒ factor 1.0 (no-op); partial fill ⇒ entry_risk_amount scaled to the filled fraction so `CalculatePositionRiskDollars` (returns it directly) does not over-state realized R.

## Why it is live-only (statement)
The MT5 Strategy Tester fills market orders **completely** (it does not simulate partial fills under Model=1 / 1-min-OHLC — every accepted market order fills in full at the modeled price), so a successful execution always has `m_trade.ResultVolume()` == requested volume. (XAUUSD+ is also FOK-only: the executor's entry path uses `m_trade.Buy()/Sell()` with CTrade auto-selecting the symbol's filling mode — `CEnhancedTradeExecutor.mqh:1508/1512` — and never overrides it to a partial-capable mode; the only `SetTypeFilling(ORDER_FILLING_FOK)` calls in the repo are in exit/trailing plugins on SEPARATE trade objects, not entries.) Therefore in the tester:
1. `MathAbs(executedLots - expectedLots) <= 0.001` is always true → the new partial-fill WARN branch in `ValidateExecutedVolume` NEVER executes; and the kept `executedLots <= 0` reject is identical to the old code's first clause on every full fill (a full fill is never <= 0).
2. `exec_result.executedLots == lot_size` → `filled_lots == lot_size` at orchestrator:704 → `position.lot_size` is byte-identical to the old `= lot_size`, so the downstream original/remaining seeding is unchanged, AND the `entry_risk_amount` scaling guard `filled_lots != lot_size` is FALSE → the scaling is a no-op (factor exactly 1.0).

⇒ All seeding (original/remaining/entry_risk) and every trade decision are unchanged → trade-for-trade, SL-for-SL, R-for-R identical. The fix only changes behavior on a REAL broker partial fill, which the tester cannot produce.
