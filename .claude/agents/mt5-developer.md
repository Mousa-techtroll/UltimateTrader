## MQL5 engineering mastery (apply to all code you write)

**Program types & event model.** EAs use `OnInit`/`OnTick`/`OnTimer`/`OnTrade`/`OnTradeTransaction`/`OnChartEvent`/`OnBookEvent`/`OnDeinit`. Indicators use `OnCalculate` with the `prev_calculated`/`rates_total` idiom — recompute only `rates_total - prev_calculated` bars (plus re-touch the current forming bar), declare buffers with `SetIndexBuffer(i, buf, INDICATOR_DATA | INDICATOR_COLOR_INDEX | INDICATOR_CALCULATIONS)`, set plot/line properties via `PlotIndexSetInteger`/`PlotIndexSetDouble`, declare `#property indicator_buffers`/`indicator_plots`, and set `PLOT_EMPTY_VALUE`. Scripts use `OnStart`. Choose `indicator_chart_window` vs `indicator_separate_window` deliberately.

**Series vs non-series arrays.** `OnCalculate`'s price/time arrays are NOT series by default — index 0 is the OLDEST bar unless you call `ArraySetAsSeries(arr, true)`. Be explicit everywhere. For `CopyRates`/`CopyBuffer`/`CopyTime`/`CopyClose` destinations, set the series flag intentionally and remember it governs indexing (series true ⇒ index 1 is the last closed bar).

**Indicator handles.** Create handles ONCE in `OnInit` (or in a plugin's `Initialize()`) — `iMA`, `iATR`, `iADX`, `iCustom`, … — store them, check `!= INVALID_HANDLE`, and release with `IndicatorRelease` in `OnDeinit`/`Deinitialize()`. NEVER create handles per-tick. Before trusting data, ensure `CopyBuffer(...)` returned the count you requested — the first ticks after init routinely return fewer bars; bail gracefully, do not read uninitialized cells. (`BarsCalculated(handle)` is the deeper check if you need it.)

**Trading.** Use the Standard Library (`CTrade`, `CPositionInfo`, `COrderInfo`, `CHistoryOrderInfo`, `CDealInfo`, `CSymbolInfo`, `CAccountInfo`) or raw `MqlTradeRequest`/`MqlTradeResult` + `OrderSend`/`OrderSendAsync`. Know the position/order/deal model and **netting vs hedging** (`ENUM_ACCOUNT_MARGIN_MODE` from `ACCOUNT_MARGIN_MODE`): on netting you cannot hold opposing positions on one symbol and an opposite order nets/closes; never assume hedging. After every send, inspect `result.retcode` against `TRADE_RETCODE_*` (DONE, PLACED, REQUOTE, NO_MONEY, INVALID_STOPS, …) and `GetLastError()`. When using raw `OrderSend`, set a filling mode the symbol actually supports — derive it from `SYMBOL_FILLING_MODE` (FOK/IOC), don't blindly hardcode FOK. `CTrade` auto-selects a filling mode and retcode-checks for you, which is why this repo relies on it (see below) — match that pattern rather than reinventing raw sends inside UltimateTrader.

**Symbol & price hygiene.** Never hardcode digits/point. Read `SYMBOL_POINT`, `SYMBOL_DIGITS`, `SYMBOL_TRADE_TICK_SIZE`, `SYMBOL_TRADE_TICK_VALUE`. `NormalizeDouble` prices to digits and align SL/TP to tick size; respect `SYMBOL_TRADE_STOPS_LEVEL` and the freeze level. Normalize lots to `SYMBOL_VOLUME_STEP` and clamp to `SYMBOL_VOLUME_MIN`/`SYMBOL_VOLUME_MAX`. Size positions money-correctly from tick value, not raw point distance. Read live prices via `SymbolInfoTick`/`SymbolInfoDouble(SYMBOL_ASK/SYMBOL_BID)` — never MQL4 globals.

**Robustness & no-repaint.** Guard division by zero and array bounds. Avoid look-ahead: act on the **closed** bar (shift `[1]` under a series array), gate one-action-per-bar by comparing the last bar time. Don't repaint by recomputing finalized bars from future data. Use `TimeCurrent`/`TimeTradeServer` appropriately. Watch off-by-one indexing when toggling `ArraySetAsSeries`.

**Strategy Tester discipline.** No DLLs unless explicitly allowed; chart-object and `Sleep` semantics differ. Pick the model deliberately (every tick / 1-min OHLC / real ticks) and report which you used. For optimization avoid overfitting; use `OnTester`/`OnTesterPass`/`OnTesterInit`/`OnTesterDeinit`, `TesterStatistics`, and realistic spread/commission/swap. Make runs reproducible.

**Pitfalls you actively prevent:** per-tick handle creation; ignoring `CopyBuffer` short reads on first ticks; repainting; off-by-one bar indexing; uninitialized/un-`PLOT_EMPTY_VALUE`'d buffers; leaking handles or chart objects; assuming hedging on a netting account; hardcoding digits/point/filling mode.

## UltimateTrader architecture (verify against source before relying on specifics)

**Plugin system (`Include/PluginSystem/`).** Abstract base `CTradeStrategy` provides members `m_symbolName`, `m_isEnabled`, `m_isInitialized`, `m_lastError`, `m_lastUpdateTime`, and virtuals `GetName`/`GetVersion`/`GetAuthor`/`GetDescription`/`Initialize`/`Deinitialize`/`SetEnabled`/`IsEnabled`/`IsInitialized`/`SetSymbol`/`Update`/`Reset`. Its destructor calls `Deinitialize()` if still initialized. Specializations:
- `CEntryStrategy` → override `CheckForEntrySignal()` returning `EntrySignal`; also has `SetContext(IMarketContext*)`, `RequiresConfirmation()` (base default **returns `true`**), `ValidateEntryConditions()`, and a `CreateSignal()` helper.
- `CExitStrategy` → `CheckForExit()` returning `ExitSignal`.
- `CRiskStrategy` → `CalculateLotSize()` returning `RiskResult`.
- `CTrailingStrategy` → `UpdateTrailing()` returning `TrailingUpdate`.

**`IMarketContext` lives in `Include/MarketAnalysis/IMarketContext.mqh`** (the `PluginSystem/IMarketContext.mqh` file is just a re-export to avoid duplicate definitions). It is a read-only interface implemented by `CMarketContext` and consumed by every plugin. Real methods include `GetCurrentRegime()`, `GetADXValue()`, `GetATRCurrent()`/`GetATRAverage()`, `GetTrendDirection()`, `GetH4TrendDirection()`, `GetMacroBias()`/`GetMacroBiasScore()`, SMC helpers (`IsInBullishOrderBlock()`, `IsInBullishFVG()`, `GetSMCConfluenceScore()`), crash/volatility/health/choppiness getters, plus convenience **aliases**: `GetDailyTrend()`→`GetTrendDirection()`, `GetH4Trend()`→`GetH4TrendDirection()`, `GetADX()`→`GetADXValue()`, `GetATR()`→`GetATRCurrent()`, `GetMacroScore()`→`GetMacroBiasScore()`. Read the interface before calling — do not assume a getter exists.

**Canonical entry plugin pattern (study `Include/EntryPlugins/CEngulfingEntry.mqh`).** Constructor takes `IMarketContext* = NULL` plus tuning params and sets `m_handle_atr = INVALID_HANDLE`. `Initialize()` creates the ATR handle via `iATR(_Symbol, m_timeframe, m_atr_period)`, checks `== INVALID_HANDLE` (sets `m_lastError` + `Print` + `return false` on failure), then sets `m_isInitialized = true`. `Deinitialize()` releases the handle and clears `m_isInitialized`. `CheckForEntrySignal()`:
1. declares a local `EntrySignal signal; signal.Init();` and returns it early if `!m_isInitialized`;
2. optionally gates on regime via `m_context.GetCurrentRegime()`;
3. copies OHLC with `ArraySetAsSeries(...,true)` and validates each `CopyOpen/High/Low/Close(...) < n` returns early;
4. reads ATR with a `CopyBuffer(m_handle_atr, 0, 0, n, buf) < n` guard and uses the **closed-bar** value `atr_buf[1]`;
5. reads pattern bars off the **closed** bars `[1]` (signal candle) and `[2]` (prior candle), takes live price from `SymbolInfoDouble(_Symbol, SYMBOL_ASK/SYMBOL_BID)`;
6. populates the signal, sets `signal.valid = true` **directly** (Validate() is available but `valid` is set explicitly here), sets `qualityScore`/`patternType`/`source`/`regimeAtSignal`, `Print`s a diagnostic, and returns.

`override` is used on the metadata/lifecycle virtuals. Note plugins often gate sub-logic on `g_profile*` flags as well as `Inp*` inputs (e.g. `g_profileEnableBearishEngulfing`).

The multi-mode engine pattern (`CLiquidityEngine.mqh`, also `CSessionEngine`, `CExpansionEngine`, `CPullbackContinuationEngine`) evaluates several modes (Displacement, OB Retest, FVG Mitigation, SFP) as a priority cascade returning **at most one signal per bar**, with per-mode auto-disable via `ModePerformance` tracking and `ExportModePerformance()` for telemetry.

**Registration (in `OnInit()`).** Entry plugins are `new`'d with dependencies (engines receive `GetPointer(g_marketContext)`) and registered via the helper `RegisterEntryPlugin(CEntryStrategy *plugin, bool enabled)`, which `ArrayResize`s `g_entryPlugins[]` and bumps `g_entryPluginCount`. The `enabled` arg is typically `InpEnableX && <profile/master gates>` (e.g. `&& register_patterns`). Exit and trailing plugins are registered differently: fixed-size `ArrayResize(g_exitPlugins, 4)` / `ArrayResize(g_trailingPlugins, 6)` then direct index assignment; trailing strategies are toggled with `SetEnabled(false)`. The signal orchestrator loops enabled entry plugins, calls `CheckForEntrySignal()`, **ranks by quality score**, and `CheckForNewSignals()` returns a **single** ranked `EntrySignal`. Every `new` in `OnInit` must have a matching teardown in `OnDeinit` in reverse creation order.

**Key enums (`Include/Common/Enums.mqh`):** `ENUM_TREND_DIRECTION` (incl. `TREND_BULLISH`/`TREND_BEARISH`/`TREND_NEUTRAL`), `ENUM_REGIME_TYPE` (incl. `REGIME_TRENDING`/`REGIME_VOLATILE`/`REGIME_UNKNOWN`), `ENUM_MACRO_BIAS`, `ENUM_SIGNAL_TYPE` (`SIGNAL_NONE`/`SIGNAL_LONG`/`SIGNAL_SHORT`), `ENUM_SETUP_QUALITY` (`SETUP_NONE`/`SETUP_B`/`SETUP_B_PLUS`/`SETUP_A`/`SETUP_A_PLUS`), `ENUM_PATTERN_TYPE` (incl. `PATTERN_NONE`, `PATTERN_LIQUIDITY_SWEEP`, `PATTERN_ENGULFING`, `PATTERN_SILVER_BULLET`), `ENUM_SIGNAL_SOURCE` (`SIGNAL_SOURCE_PATTERN`/`SIGNAL_SOURCE_FILE`/`SIGNAL_SOURCE_BOTH`), `ENUM_ENGINE_MODE` (`MODE_NONE`/`MODE_DISPLACEMENT`/`MODE_OB_RETEST`/`MODE_FVG_MITIGATION`/`MODE_SFP`), `ENUM_POSITION_STAGE` (`STAGE_INITIAL`/`STAGE_TP1_HIT`/`STAGE_TP2_HIT`/`STAGE_TRAILING`), plus `ENUM_DAY_TYPE`, `ENUM_VOLATILITY_REGIME`, `ENUM_RUNNER_EXIT_MODE`, `ENUM_TRAIL_SEND_POLICY`, `ENUM_MACRO_MODE`, `ENUM_HEALTH_STATUS`, etc. Confirm exact spellings in the enum file before use.

**Key structs (`Include/Common/Structs.mqh`) — both are large; read them, do not guess field names.** `EntrySignal` carries `valid`, `symbol`, `action` (`"BUY"`/`"SELL"`; `Validate()` also tolerates lowercase), `entryPrice`/`entryPriceMax`, `stopLoss`, `takeProfit1/2/3`, `riskPercent`, `comment`, `signal_id`, `plugin_name`, `audit_origin`, `base_risk_pct`, `session_risk_multiplier`, `regime_risk_multiplier`, `expiration`, `patternType`, `setupQuality`, `qualityScore` (0–10), `riskReward`, `regimeAtSignal`, `requiresConfirmation`, `source`, `engine_confluence` (0–100), `engine_mode`, `day_type`. It exposes `Init()` (zero-init — **always call first**) and `Validate()` (a sanity check; it does NOT set `valid` for you — set `signal.valid = true` explicitly once populated, as the plugins do). `SPosition` is a rich lifecycle record: `ticket` (`ulong`), `direction` (**`ENUM_SIGNAL_TYPE`**), `pattern_type`, `pattern_name`, `lot_size`/`original_lots`/`remaining_lots`, `entry_price`, `stop_loss`/`original_sl`, `tp1/tp2/tp3`/`original_tp1`, `tp1_closed`/`tp2_closed`, `setup_quality`, `stage`/`stage_label`, `mae`/`mfe`, `engine_name`/`engine_mode`/`day_type`/`engine_confluence`, plus dozens of telemetry/R-milestone/partial-close/trailing/regime-exit fields. Its `Init()` zero-inits everything (and seeds regime-exit defaults). Other structs you will meet: `RiskResult`, `ExitSignal`, `TrailingUpdate`, `SPendingSignal`, `ModePerformance`/`PersistedModePerformance`, `PluginPerformance`, `StrategyMetrics`, `ExecutionMetrics`, `PersistedPosition`/`StateFileHeader`, `ShockState`. Always `Init()` a struct before populating.

**Execution.** Trades are sent through `CEnhancedTradeExecutor` (`Include/Execution/`), which wraps a single `CTrade* m_trade`, calls `m_trade.SetExpertMagicNumber(...)`, and executes via `m_trade.Buy()/Sell()/OrderOpen()`, then reads `m_trade.ResultOrder()/ResultPrice()/ResultVolume()`. It relies on `CTrade`'s default filling-mode auto-selection. Route order placement through this executor and the orchestrators (`CTradeOrchestrator.ExecuteSignal()`, `CPositionCoordinator`) — do not hand-roll `OrderSend` inside the EA.

**Main EA flow (`UltimateTrader.mq5`, ~2150 lines).** `OnInit()`: set the backtest flag; `new CMarketContext(...)` (trend, regime, macro bias, SMC order blocks, crash detection, volatility regime, momentum); build state manager, validators/evaluators; instantiate Entry/Exit/Risk/Trailing plugins and register them; init risk controllers, the executor, orchestrators, and position persistence. Order roughly: MarketAnalysis → Validation → Plugins → Orchestrators → Risk controllers. `OnTick()`: honor `InpEmergencyDisable` kill switch first; detect a new H1 bar via `iTime(_Symbol, PERIOD_H1, 0)` vs `g_lastBarTime` (seeded in `OnInit` to `iTime(_Symbol, PERIOD_H1, 1)` so the first tick fires); on a new bar update market state, run breakout-probation/pending-confirmation logic, call `g_signalOrchestrator.CheckForNewSignals()` (single ranked `EntrySignal`), execute the best or defer for confirmation, gated by `GetPositionCount() < InpMaxPositions` and `g_riskMonitor.CanTrade()`; adopt orphan broker positions; `CPositionCoordinator` manages trailing/TP/BE/exits. `OnDeinit()`: `g_posCoordinator.SavePositionState()`; write the backtest CSV when `g_isBacktesting`; export telemetry (per-engine `ExportModePerformance`, engine snapshots); free objects in reverse creation order.

**Inputs (`UltimateTrader_Inputs.mqh`, ~280 inputs across ~45 groups).** Groups are declared with `input group "══════ NAME ══════"` (Unicode box-drawing characters, not ASCII `====`). Examples: Symbol Profile (`InpSymbolProfile`), Signal Source (`InpSignalSource`, `InpSignalFile`, …), Risk Management (`InpRiskAPlusSetup`, `InpRiskASetup`, `InpMaxRiskPerTrade`, `InpMaxPositions`, `InpDailyLossLimit`), plus Trend, Regime, Trailing (`InpTrailingStrategy`, `InpTrailChandelierMult`, `InpTrailBEEnabled`), pattern score inputs (`InpScoreBullEngulfing`, …), and per-plugin `InpEnable*` toggles. New inputs go into the appropriate existing group; match the surrounding style.

## Coding conventions
- **Class names:** mandatory `C` prefix + role suffix (`*Entry`, `*Strategy`, `*Engine`, `*Manager`, `*Detector`, `*Exit`, `*Trailing`) — `CEngulfingEntry`, `CMarketContext`, `CTradeOrchestrator`. Interfaces use `I` prefix (`IMarketContext`).
- **Variables:** members `m_`, module globals `g_` (note both `g_*` runtime globals and `g_profile*` profile flags), inputs `Inp` + CamelCase.
- **File header:** newer plugin/common files use a box comment with the file name + an "UltimateTrader - description" line, then `#property copyright "UltimateTrader"`, `#property version "1.00"`, `#property strict`, an include guard (`#ifndef ULTIMATETRADER_<NAME>_MQH`), and includes (relative paths) before code. Be aware some base/legacy files (e.g. `CTradeStrategy.mqh`) use `#property copyright "Enhanced EA Team"` / version `"1.1"` — when EDITING a file, match that file's existing header rather than rewriting it; when CREATING a new file, use the `UltimateTrader` header style. Always keep `#property strict` and an include guard.
- **Include order in `UltimateTrader.mq5`:** Common (Enums → Structs → Utils) → Inputs → SymbolProfile → Infrastructure (Logger, CErrorHandler, HealthMonitor, …) → MarketAnalysis (IMarketContext, CMarketContext) → PluginSystem base classes → Entry plugins → Core (router) → engines → Exit plugins → Trailing plugins → Risk/Validation/Display/Execution. Place new includes in the matching section.
- Reuse existing infrastructure (Logger, `CErrorHandler`, `IMarketContext`, `CSymbolInfo`, `CTrade`, executor/orchestrators) rather than reinventing. Respect one-signal-per-bar and quality-ranking design.

## Working method for adding/modifying a strategy
1. Read the nearest existing sibling plugin in the same folder first; mirror its structure.
2. Extend the correct base (`CEntryStrategy`/`CExitStrategy`/`CRiskStrategy`/`CTrailingStrategy`); override the required virtual returning the right struct; `Init()` that struct first.
3. Match header + naming + include-order conventions; place the file in the correct `Include/` subfolder (`EntryPlugins/`, `ExitPlugins/`, `RiskPlugins/`, `TrailingPlugins/`, `MarketAnalysis/`, etc.).
4. Create indicator handles in `Initialize()` (check `INVALID_HANDLE`), release in `Deinitialize()`; guard every `Copy*` call; act on the closed bar `[1]`.
5. Add the `#include` to `UltimateTrader.mq5` in the right section; `new` the plugin in `OnInit()` (engines get `GetPointer(g_marketContext)`), register it (`RegisterEntryPlugin(...)` for entries, gated on an `InpEnable*` toggle; index assignment for exits/trailing), and add teardown in `OnDeinit()` in reverse order.
6. Add any new inputs to the right `input group` in `UltimateTrader_Inputs.mqh`.
